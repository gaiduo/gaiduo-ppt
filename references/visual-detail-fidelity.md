# 细节保真合同

本文件用于防止“大结构接近，但设计感细节丢失”的问题。适用于阶段三和阶段四。

## 需要单独锁定的细节

以下元素不是可随意省略的装饰；只要在阶段三视觉稿中出现，就必须进入 `visual_detail_contract.md` 和 `asset_plan.json`：

- 信息型小图标、线性图标、反白图标、品牌符号；
- 虚线、引线、连接线、端点圆点、箭头、括号、辅助标尺；
- 图形节点、编号圆点、标签锚点；
- 金字塔、漏斗、飞轮、循环图、流程图、矩阵、地图、关系网的整体几何关系；
- 多层图形的共用边线、中心轴、角度、层间间距和闭合轮廓。

## 图标规则

图标分三类：

1. `semantic-icon`：表达含义的信息图标，例如价格、门店、供应链、研究范围。必须用 SVG、icon font、局部图片或明确绘制的矢量图形还原。
2. `brand-icon`：品牌角色、品牌符号、产品轮廓。不得用通用图标替代，必要时作为局部图片模块嵌入。
3. `decorative-icon`：纯装饰图标。可以简化，但不能影响页面节奏和视觉质感。

默认规则：

- 不得用汉字、emoji、标点、百分号、首字母或普通文本代替图标；
- 不得把多个不同图标统一替换成同一个圆点或方块；
- 若图标无法可靠重画，应在阶段三导出为局部 SVG/PNG 素材。

## 连接线规则

虚线、引线和端点属于信息结构时，必须保留：

- 记录起点、终点、连接对象和线型；
- 记录实线 / 虚线、颜色、粗细、端点圆点、箭头方向；
- 文本标签与图形节点之间的连接关系必须可见；
- 不得因为“文字已经在旁边”就删除连接线。

## 几何拓扑规则

金字塔、漏斗、飞轮、循环图等整体图形必须先定义拓扑，再实现局部形状。

阶段三应记录：

- 图形类型；
- 中心轴或中心点；
- 外轮廓；
- 分层 / 分段数量；
- 每层 / 每段的相邻关系；
- 共用边、闭合关系、角度一致性；
- 标签与图形区域的绑定关系。

阶段四实现时：

- 优先用一个统一 SVG `viewBox` / `clipPath` / `path` 系统生成，不要用多个互不关联的 CSS 多边形随手拼；
- 多层金字塔应共用同一个外轮廓和中心轴；
- 飞轮每段必须形成连续闭环，节点、引线和标签必须随段落锚定；
- 若局部路径重建会明显变形，应把该关系图作为局部 `visual-module` 嵌入，并叠加可见 HTML 文本。

## 阶段三产物要求

创建 `visual_detail_contract.md`，逐页列出：

- `micro_icons`：每个图标的含义、位置、样式、实现方式、是否允许替代；
- `connectors`：每条线/虚线/箭头的起点、终点、样式、绑定对象；
- `geometry_topology`：金字塔、飞轮、漏斗、矩阵等整体几何约束；
- `must_not_replace_with_text`：禁止用文字或符号代替的图标；
- `qa_items`：阶段四必须截图核对的细节。

在 `asset_plan.json` 中，关键 `chart` 或 `svg-css` 元素必须包含 `detail_contract`，至少覆盖 `micro_icons`、`connectors` 或 `geometry_topology` 之一。

## 阶段四 QA 要求

逐页对照 `visual_detail_contract.md` 检查：

- 图标是否存在，是否被文字 / emoji / 标点替代；
- 虚线、引线、端点和箭头是否存在；
- 金字塔、飞轮、漏斗等整体几何是否闭合、对齐、角度一致；
- 标签是否仍然锚定在正确图形节点上；
- 辅助细节缺失是否降低页面设计感。

缺少信息型图标、连接线、节点锚点或整体几何失真，默认按 P2 处理；如果影响核心关系理解，按 P1 处理。
