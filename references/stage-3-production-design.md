# 阶段三：视觉定稿与生产资料

## 目标

把用户选定的阶段二视觉方向转成可被阶段四高保真还原的生产资料。阶段三不是重新设计，而是视觉锁定、高清化、素材化和混合还原规划。

## 输入优先级

1. 用户最新明确修改；
2. 最终选定的阶段二拼图和用户确认；
3. 已确认演示大纲；
4. 源文档。

阶段二拼图决定视觉方向、页面轮廓、主视觉、图表类型、页面节奏和信息取舍。演示大纲和源文档用于修正文案、数字、单位、口径和缩略图看不清的内容，不得用来恢复用户删除的内容或重写页面。

## 步骤一：最终内容规范

创建 `final_content_spec.md`。逐页记录：

- 页码；
- 页面标题；
- 核心观点/副标题；
- 页面需要显示的完整文字；
- 页面需要显示的数字、年份、单位和口径；
- 明确禁止出现的内容；
- 与原演示大纲相比发生的变化。

不得留下“待核验”“TODO”“缺失数据”等展示占位。若核心内容无法从文档或用户信息确认，应暂停说明。

## 步骤二：逐页视觉锁定清单

创建 `visual_lock_spec.md`。逐页锁定：

- 页面背景、主色、辅助色、纹理和整体气质；
- 页面构图轮廓和主要模块数量；
- 主视觉模块和视觉重心；
- 图表或关系图类型；
- 品牌、产品、人物、地图、门店、设施、界面、纹理等关键视觉资产；
- 标题、副标题、证据、注释和页码的大致区域；
- 页面与前后页的节奏关系；
- 允许高清化时调整的细节；
- 明确禁止改变的内容。

同时创建 `visual_detail_contract.md`，专门锁定容易被阶段四遗漏的细节：

- 信息型小图标、线性图标、反白图标和品牌符号；
- 虚线、引线、端点圆点、箭头、节点锚点；
- 金字塔、漏斗、飞轮、循环图、矩阵、地图等整体几何拓扑；
- 哪些图标禁止用文字、emoji、符号或首字母替代；
- 阶段四逐页 QA 必须检查的细节项。

写法见 `references/visual-detail-fidelity.md`。没有复杂图形的页面也要写“本页无必锁定微视觉元素”，避免阶段四自行判断。

以下变化默认判定为失败，不得继续：

- 强品牌风变成极简白底风；
- 地图变成无语义点阵；
- 供应链、机制图、增长飞轮、产品矩阵变成普通卡片；
- 品牌/产品/人物/门店/场景资产大幅减少；
- 复杂视觉模块被基础形状替代；
- 页面主视觉焦点、图表类型或构图轮廓改变；
- 为了 HTML 好做而降低设计质感。

## 步骤三：混合还原策略

创建 `rendering_strategy.md` 和 `asset_plan.json`。逐页拆分：

- `html-text`：标题、正文、数字、单位、表格文本、图表标签等权威文字；
- `chart`：需要数据准确、可控的图表；
- `svg-css`：简单线条、边框、箭头、基础几何和普通图标；
- `raster`：独立照片、产品图、透明物体、品牌物料；
- `visual-module`：复杂插画、地图底图、场景组合、品牌纹理、复杂机制图、难以拆开的视觉组。

原则：能拆且不损失质感的才拆；拆开会明显退化的，作为一个视觉模块保真嵌入。不要为了可编辑性牺牲视觉效果。

每个主要元素都要记录来源、目标区域、适配方式、是否允许裁切、是否允许简化、是否允许阶段四重新生成。关键视觉模块默认不允许简化、不允许重新生成。

关键 `chart` 或 `svg-css` 元素必须带 `detail_contract` 字段，说明：

- `micro_icons`：图标数量、含义、位置和实现方式；
- `connectors`：虚线、引线、端点、箭头和绑定对象；
- `geometry_topology`：整体几何类型、中心轴 / 中心点、外轮廓、分层 / 分段数量、角度一致性和闭合关系；
- `text_substitution_forbidden`：是否禁止用文字或符号替代图标。

例如金字塔不能只写“三层梯形”；必须写明共用中心轴、统一外轮廓、三层斜边角度一致。飞轮不能只写“五步闭环”；必须写明五段环形箭头、节点图标、虚线引导和标签锚定。

### 整页视觉稿禁止作为运行时素材

阶段三的 `slide_01.png` 到 `slide_NN.png` 是整页视觉参考，只能用于：

- 用户确认；
- 阶段四同画面对比；
- 视觉锁定和 QA。

不得把这些整页视觉稿写入 `asset_plan.json` 的元素 `source`，也不得把它们标记为 `raster` 或 `visual-module` 的运行时素材。运行时图片素材必须是局部素材，放在 `assets/production/`，例如产品图、门店照片、地图底图、品牌角色、背景纹理或复杂机制模块。

除非用户明确授权整页图片化，否则 `asset_plan.json` 不得出现：

- `source` 指向 `stage3_production/slides/slide_*.png`；
- `source` 指向 `slides/slide_*.png`；
- `target_box` 接近整页的 `raster` 或 `visual-module`；
- 用一个主要图片模块覆盖页面大部分内容。

如果某页确实无法拆分且用户授权整页图片化，必须在计划顶层写明：

```json
{
  "user_authorized_full_slide_raster": true,
  "full_slide_raster_reason": "用户明确要求像素保真优先并接受页面不可编辑"
}
```

未授权时，阶段四必须按局部素材 + 可见 HTML 文本 + 可控图表的方式还原。

运行 `scripts/validate_asset_plan.py` 检查计划。若失败，先修计划。

## 步骤四：生成逐页高清视觉稿和素材

生成 `slide_01.png` 到 `slide_NN.png`：

- 每张只包含一页；
- 严格 1920×1080、16:9；
- 正面平视，四边完整；
- 高保真还原选定阶段二拼图；
- 使用 `final_content_spec.md` 的文字和数字；
- 不得引入新视觉方向。

阶段三必须逐页输出和展示独立高清视觉稿。不得只输出联系表、总览图、拼图链接或缩略预览来替代逐页高清稿。若页面较多，也必须提供逐页可打开的文件清单，并在回复中优先展示或链接每一页独立高清稿。

同时准备 `assets/production/` 中阶段四需要使用的图片模块、透明素材和复杂视觉模块。

`assets/production/` 应包含阶段四真正可用的局部素材。不得只准备整页 `slide_*.png` 后让阶段四从整页图中偷懒裁切；如果需要局部图片模块，应在阶段三明确导出或生成对应的局部素材，并在 `asset_plan.json` 中记录它的目标区域和保真要求。

## 步骤五：阶段三 QA

创建 `stage3_fidelity_qa.md`，逐页对比阶段二拼图和阶段三高清稿：

- 构图轮廓是否一致；
- 主视觉是否一致；
- 图表类型是否一致；
- 品牌和产品资产是否保留；
- 背景、纹理、配色和视觉气质是否一致；
- 信息层级是否一致；
- 是否发生简化、抽象化或模板化；
- 是否存在文字、数字、单位错误。

发现 P0/P1/P2 问题必须重做对应页面或素材。不要把失败页面展示为已完成。

## 输出和暂停

展示逐页独立高清视觉稿，并提供：

- `final_content_spec.md`
- `visual_lock_spec.md`
- `visual_detail_contract.md`
- `rendering_strategy.md`
- `asset_plan.json`
- `assets/production/`
- `stage3_fidelity_qa.md`

不要生成阶段三联系表或总览拼图，除非用户在当前阶段明确要求。即使用户要求生成，总览图也只能作为附加索引，不能替代逐页高清视觉稿和逐页 QA。

完成后暂停，等待用户确认。不要开始编写 HTML。
