# 阶段四：HTML 混合还原

## 目标

根据阶段三确认的高清视觉稿、最终内容规范、视觉锁定清单、素材和混合还原策略，完成整套 HTML 版 PPT。阶段四只执行和 QA，不重新设计。

## 权威来源

1. `final_content_spec.md` 控制最终文字、数据、单位、年份和口径；
2. 阶段三高清视觉稿控制页面版式、层级、配色、图表语言、图片语言和整体质感；
3. `visual_lock_spec.md` 控制不得改变的视觉结构；
4. `rendering_strategy.md` 和 `asset_plan.json` 控制每个元素的实现方式；
5. `visual_detail_contract.md` 控制微型图标、连接线和几何拓扑；
6. `assets/production/` 控制可使用的图片和视觉模块。

不得根据旧大纲、源文档或自己的判断恢复已删除内容。不得重新提炼报告。

## 混合还原规则

最终 HTML 不是全部代码化，而是高保真混合还原：

- 标题、正文、数字、单位、表格文字必须是真 HTML；
- 数据图表优先用 HTML/CSS/SVG/Canvas 或图表组件；
- 简单线条、色块、边框、箭头和普通图标可用 HTML/CSS/SVG；
- 复杂插画、产品图、地图、门店场景、人物、品牌形象、背景纹理、复杂机制图可作为图片模块；
- 拆开会损失质感的元素必须作为整体视觉模块嵌入；
- 不允许为了提高 HTML 可编辑性而牺牲已确认视觉稿的设计质感。

阶段四不得调用图片生成，不得替换已确认素材，不得把复杂视觉模块重画成简化版本。

阶段四也不得把阶段三整页高清视觉稿当成运行时页面主体。`stage3_production/slides/slide_01.png` 到 `slide_NN.png` 只能用于视觉对比，不得作为整页 `<img>`、整页背景、主要 slide layer 或覆盖页面大部分区域的 `visual-module`，除非用户在当前阶段明确授权 `full-slide-raster`。

### 禁止“整页图 + 透明语义层”

以下实现属于 P0 失败，必须重做：

- 页面可见主体是一张整页视觉稿图片；
- 标题、正文、数字虽然存在于 DOM，但通过透明、低透明度、离屏、极小字号或被图片遮盖而不可见；
- 普通观众看到的文字主要来自图片，而不是真 HTML；
- QA 记录把整页视觉稿称为“等价截图”或“主视觉层”来代替真实浏览器截图。

权威文字必须作为可见 HTML 显示：标题、正文、数字、单位、表格文字、图表标签、注释的 `opacity` 和文字颜色 alpha 不得低于 0.85，不能 `display:none`、`visibility:hidden`、离屏隐藏或被整页图片覆盖。

## 实现要求

- 每页固定 1920×1080 设计画布；
- 浏览器窗口变化时整页等比例缩放，不改变内部构图；
- 支持上一页、下一页、方向键、页码、全屏和刷新后的初始状态；
- 项目资源使用相对路径；
- 不把整张页面截图作为唯一背景，除非用户明确授权像素保真优先；
- 复杂视觉模块可以局部图片化，但权威文字和关键数字仍应是真 HTML。
- 局部图片模块应来自 `assets/production/`，不直接引用阶段三整页 `slide_*.png`；
- 如果 `asset_plan.json` 校验失败，不得继续生成 HTML。
- 生成 HTML 后运行 `scripts/validate_html_rendering.py`。若失败，必须修复后重新运行，不得交付。
- 关键 `chart` / `svg-css` 必须按 `visual_detail_contract.md` 还原图标、虚线、引线、端点和几何拓扑。
- 不得用汉字、emoji、标点、百分号、首字母或普通文本替代信息型图标；若图标无法高质量 CSS/SVG 重画，应回到阶段三补局部 SVG/PNG 素材。
- 金字塔、漏斗、飞轮、循环图等整体关系图优先用统一 SVG `viewBox` / `path` / `clipPath` 实现，避免用多个独立 CSS 多边形拼出角度不一致的结构。

## QA

先选择封面、最复杂机制页、最数据密集页作为校准页。实现后截图，与阶段三高清视觉稿同画面对比，修复 P0/P1/P2 问题后再做全套。

全套完成后逐页截图对比，检查：

- 页面数量和顺序；
- 文本、数字、单位、口径；
- 构图轮廓、主视觉、图表类型；
- 背景、纹理、配色、字体层级；
- 图片裁切、透明背景、边缘杂色；
- 是否有复杂视觉被简化；
- 是否有品牌、产品、地图、场景资产被替换；
- 信息型小图标是否存在，是否被文字或符号替代；
- 虚线、引线、端点圆点、箭头和节点锚点是否存在；
- 金字塔、漏斗、飞轮、循环图的外轮廓、中心轴、角度、闭合关系是否与高清视觉稿一致；
- 是否有文字重叠、溢出、裁切或缺失；
- 交互是否正常；
- 浏览器控制台是否报错。

额外硬检查：

- HTML/CSS/JS 中不得引用阶段三整页视觉稿作为页面主体；
- 不得存在 `.slide-image`、`.semantic-layer` 等把整页图作为可见层、把真实文字藏起来的结构；
- 可见 HTML 文本必须能在截图中被读到，而不是只存在于 DOM；
- 浏览器截图必须来自真实 HTML 渲染，不得用阶段三视觉稿冒充最终截图。

P0：页面缺失、内容严重错误、无法演示、核心视觉完全错误。

P1：主视觉、图表类型、构图轮廓、品牌资产、复杂视觉模块明显改变或退化。

P2：明显位置、比例、裁切、对齐、层级、色彩或文字问题，影响普通观众观感；信息型图标缺失、虚线/引线缺失、节点锚点缺失、几何角度不统一也默认属于 P2。

P3：轻微 polish，不影响理解和展示，可记录但不阻塞。

修复流程为：修改、截图、对比、再修改。不得用“接近”替代明确失败项。
